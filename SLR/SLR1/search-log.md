## Search strategy notes
- The search strategy followed four main concept clusters implied by the protocol:
  1. **General nanosatellite/CubeSat MBSE reference-model lineage**: reference models, standardized templates, behavior modeling, mission/system modeling architecture.
  2. **EPS / power / electrical-architecture lineage**: power subsystem, power-budget, electrical architecture, traceability, EPS-adjacent model structure.
  3. **Verification / validation / test lineage**: V&V, IVV, test and evaluation, requirements-in-loop, automated testing.
  4. **Outcome / integration lineage**: traceability, integration, reproducibility, data formalization, MBSE/PLM linkage.
- Earlier continuation work had already recovered `Enterprise modeling for CubeSats`, audited the `Rapid...`, `SPARC-1...`, and `FloripaSat-2...` gaps, rerun the broad mission query at full depth, and incorporated the manual IEEE Xplore audit.
- The later recall pass focused specifically on the remaining **RQ2/RQ3 sparsity question**, especially direct terminology around **EPS/power-budget**, **electrical architecture**, **requirements-verification**, **test/evaluation**, **traceability**, and alternative wording around **Capella / Arcadia / CPS**.
- The recall pass was run in two small Scopus batches (Q19-Q21, then Q22-Q24). Each saved JSON file was read back before deciding whether further refinement was justified.
- Net effect across the later continuation work: the corpus became more complete around RQ3 terminology, but the search still mainly strengthened the conclusion that **RQ2/RQ3 literature is genuinely sparse**, especially for **EPS-specific** verification/traceability/test integration.
- A final user-requested exact-title revisit added `A Model-Based Approach to Risk Management for RVSAT-1: a Student Nano-satellite Project - Using SysML` as an additional `supporting` paper, strengthening contextual nanosatellite MBSE coverage without materially changing the EPS-specific conclusion.
- A later citation-chasing continuation formalized three more user-selected additions via new exact-title searches plus local full-text metadata completion: `Developing a CubeSat System MBSE Reference Model – Interim Status #5` (`core`), `Preliminary Design of Satellite Systems through the Integration of Model-Based System Engineering and Agile Methodologies: Application to the 3ColStar Mission` (`supporting`), and `Model-based systems engineering to support the development of nanosatellites` (`core`).
- A 2026-04-24 IEEE parity addendum incorporated user-provided IEEE Xplore CSV exports `7.csv`, `23.csv`, and `24.csv`, corresponding to Scopus Q7, Q23, and Q24. The user indicated that unrun IEEE queries were intentionally deemed unnecessary. After screening against the protocol, two IEEE records were user-approved as new `core` papers and promoted into the merged candidate set and corpus: `Application of model-based systems engineering in small satellite conceptual design-A SysML approach` and `Automating Object-Oriented Functional Modeling for Standardized Design in the New Space Domain`.

### Abstract-enrichment limits encountered
- Many IEEE/AIAA / publisher-controlled records remained abstract-poor in both preferred sources even when the exact title match was recovered. Semantic Scholar frequently returned the correct paper with metadata but no abstract, and Scopus exact-title confirmation was often similarly abstract-empty.
- Google Scholar helped only as a **last-resort snippet source**; some later fallback queries failed with `Cannot Fetch from Google Scholar`, consistent with rate limiting / blocking. Those failures are preserved as placeholder JSON files in `searches/abstract_enrichment/` rather than silently omitted.
- Therefore, the revisit improved screening evidence materially, but it did **not** fully eliminate title-led screening for every kept record.

## Stopping rationale
- The targeted RQ2/RQ3 recall pass, the later exact-title revisit, and the citation-chasing continuation did **not** materially change the overall conclusion about the evidence base. They improved coverage by adding five papers in total: *Requirements Modeling Language and Automated Testing for CubeSats*, *A Model-Based Approach to Risk Management for RVSAT-1: a Student Nano-satellite Project - Using SysML*, *Developing a CubeSat System MBSE Reference Model – Interim Status #5*, *Preliminary Design of Satellite Systems through the Integration of Model-Based System Engineering and Agile Methodologies: Application to the 3ColStar Mission*, and *Model-based systems engineering to support the development of nanosatellites*.
- The continuation mainly **strengthened the case that the literature is genuinely sparse**, especially for **EPS-specific MBSE verification / IVV / test / traceability integration**.
- Direct EPS/power-budget/electrical-architecture querying (Q19) produced a very small set dominated by already-known papers plus one specialized CPS validation study that did not fit the protocol.
- Capella/Arcadia-specific probing (Q23) did **not** reveal any hidden tool-specific CubeSat MBSE literature cluster in the current Scopus scope.
- CPS-oriented alternative terminology (Q21) yielded mostly specialized or off-topic records; it did not uncover a substantial new in-scope nanosatellite MBSE corpus.
- The strongest additional RQ3-oriented refinement (Q24) found exactly one new supporting paper and no new core paper.
- The 2026-04-24 IEEE parity addendum closes the practical IEEE parity gap for the non-redundant Scopus backbone (Q7) and the two most relevant later audit/refinement lines (Q23/Q24). Because the user deemed unrun IEEE queries unnecessary, and because the remaining Scopus lines were too broad/noisy, redundant, exact-title/citation-chasing, or not used for candidate building, no further IEEE Xplore queries are recommended for parity.
- Therefore, this continuation modestly raises confidence that the search space has been tested thoroughly, but it does **not** raise RQ2/RQ3 confidence by adding a large new body of evidence. Instead, it increases confidence that the **lack of direct EPS-specific verification literature is real under the current protocol and database scope**.
- Under the protocol, current Scopus + IEEE evidence base, and title-led / abstract-aided screening conditions available here, Stage 1 is **search-saturated enough for full-text retrieval**.
