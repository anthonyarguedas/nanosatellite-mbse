# Partial CSRM to SysML v2 conversion

This is an **incomplete** conversion. See `PENDING.md` for the handoff checklist. I translated model namespaces, dependencies, and unit imports first. Diagrams remain for last. Empty package stubs do not contain the original projects' full models.

The main source is `DistroTemp/CSRM - 2025-11-18.mdzip` at commit `69c7f02` of `ObjectManagementGroup/CSRM`. The unit sources are `/Applications/Magic Systems of Systems Architect/modelLibraries/ISO-80000.mdzip` and `ISO-80000-Extension.mdzip`. I excluded the FireSat archive.

Source attribution: CubeSat System Reference Model © 2022 by the INCOSE Space Systems Working Group and OMG Space Domain Task Force, CC BY 4.0. See the CSRM repository README.

## Converted so far

- `model.sysml` maps the UML `Data` model to a SysML v2 package. It includes 16 basic unit category packages, 16 namespace imports, 73 element imports, all four model-level dependencies, and sixteen native item usages for Cameo editor customizations and a native `Duplicate Customization` item definition. It also contains eight technical measure requirement usages, nine specification part definitions (including the unlinked, source-spelled `KppB Spedification`), fourteen corrected `Refine` dependencies, and all 96 architecture part definitions. `Space Segment` owns two direct composite parts, one asserted composition constraint bound to `cubeSat`, and one user-chosen orbit binding. `CubeSat` owns nine direct composite subsystem parts, each subsetting inherited `subMass`, and a typed orbit reference. The nine subsystem definitions own 32 component parts. Thirty subset their inherited `subMass`. Two shared processor parts stay outside the rollup. Each requirement owns one `refinedSpecs` reference feature typed by its matching specification and an asserted `refineValidation` constraint bound to that feature. All eight requirements also own typed `Satisfy` assertions with explicit empty inputs because the source has no matching measure properties. Each dependency keeps its source XMI ID and original endpoints in metadata. Duplicate source relationships stay distinct. The package paths `Data::'CSRM Extentions'::Legends`, `Data::'CSRM Extentions'::'Model Constraints'::'Measure Validation'`, and `Data::'CSRM Extentions'::'Model Constraints'::Structure` remain as shells.
