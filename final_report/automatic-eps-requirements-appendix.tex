\chapter{Automatic EPS Requirements}
\label{appendix:automatic-eps-requirements}

The requirements automatically assigned to EPS elements form part of the fourth objective's deliverable, which characterizes early EPS verification and validation.
Table~\ref{tab:automatic-eps-requirements} associates each requirement statement with its EPS element, which also represents evidence for the fulfillment of the third objective.
Calculated targets are shown symbolically because their numerical values depend on the mission inputs, following the equations in Chapter~\ref{ch:design-proposal}.

Table~\ref{tab:automatic-eps-verification} provides the verification methods, pass/fail criteria, and required evidence for every automatic requirement. 100\% of requirements listed report a verification means, pass/fail criteria, and associated evidence, thus maintaining traceability from requirement to verification means to result and satisfying the fourth objective of this project.

Rows in Table~\ref{tab:automatic-eps-verification} follow the requirement order in Table~\ref{tab:automatic-eps-requirements} and use the default property bindings.
Subscript $\mathrm{avail}$ denotes supplied available energy or current capacity, and $[V_r^{\mathrm{lo}},V_r^{\mathrm{hi}}]$ denotes assigned receiving voltage limits.
Calculated inputs retain the dependencies given in Chapter~\ref{ch:design-proposal}.
All numerical measures and targets must be finite.
Cell and string counts must be native integers.
For minimum checks with a zero target, available evidence is unused except for the integer solar cell count.
A requirement passes when all its predicates are true.
Missing inputs remain unresolved, and calculation errors retain an error status.
